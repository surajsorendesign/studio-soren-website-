02 Week 1 · Review

Start with what is live

The website is what customers actually see, so it set the standard. We reviewed BrightBridge’s foundations and components against it, piece by piece, to find where the Figma library and the live site had drifted apart.

Alongside the audit we interviewed the designers and developers who use the system day to day, to understand how they work, where they get stuck and how AI already fits into their week.

04 Week 3 · Recommend

Written for Claude Code, tested against the real thing

We restructured the system around how Claude Code works: tokens it can resolve by name, components whose properties map straight to code, and a governance pack it reads before it builds anything. The team wrote twelve of those files; we checked each one against the live Figma file, corrected what had drifted, and added a thirteenth for accessibility.

Then we put it to the test. Claude rebuilt selected parts of the website. Where the output drifted, we refined the system. Prompts were tuned in the final phase.

Proof of concept

A new sales funnel page, from Figma frame to clickable HTML.

For BrightBridge’s new page for supported living providers, we ran the recommended workflow end to end. Claude read the Figma frames through MCP, used the governance pack as shared context, and turned the design into an interactive HTML artefact.

Stakeholders reviewed a prototype they could click through on desktop, tablet and mobile, with every FAQ state working, instead of a static mockup. Comments were resolved in Claude Code, and anything structural went back to the Figma canvas.
